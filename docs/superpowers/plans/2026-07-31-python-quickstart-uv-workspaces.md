# Python Quickstart uv Workspaces Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every Python quickstart one identical dependency flow — `uv sync --all-packages` then `uv run diagrid dev run` — by making the two multi-app quickstarts uv workspaces, so no virtual environment is ever activated and no sync can uninstall another app's dependencies.

**Architecture:** Every Python quickstart directory becomes a uv project sitting next to its `diagrid dev run` config. `invocation/python` and `pubsub/python` get a workspace root whose members are the existing app subdirectories, replacing two per-app locks with one root lock and one root `.venv`. `uv run` then puts `.venv/bin` on `PATH`, so the bare `uvicorn` command already in the dev configs resolves without activation.

**Tech Stack:** uv (workspaces, `uv.lock`), Robot Framework + pytest (`tools/qs-tester`), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-07-31-python-quickstart-uv-workspaces-design.md`

## Global Constraints

- Both new workspace roots declare `requires-python = ">=3.12"` and no `[build-system]` (uv then treats root and members as non-packaged, which is required — a `[build-system]` would make uv try to build them).
- README section 4 in all four Python quickstarts is exactly one bash block containing `uv sync --all-packages`.
- README section 5 in all four is exactly `uv run diagrid dev run -f <api>-quickstart.yaml --project <api>-quickstart --approve`.
- The four `diagrid dev run` config files (`*-quickstart.yaml`) must **not** be modified. `command: [uvicorn, main:app, …]` stays.
- Member `pyproject.toml` `dependencies` lists must **not** change. The Dockerfiles run `uv pip install --system .` from inside each member and depend on them.
- Never commit a `.venv`. It is already covered by `.gitignore`.
- Every commit must leave `uv run python docsync/check_readme_sync.py --all` reporting 16 of 16 in sync. The checker requires each documented command to be a substring of the harness `INSTALL` string, so README and harness changes for a given quickstart must land in the same commit.
- Run all `tools/qs-tester` commands from `tools/qs-tester`.

## File Structure

- `invocation/python/uv.lock`, `pubsub/python/uv.lock` — one joint resolution per quickstart.

- [ ] **Step 1: Write the failing test**

Create `tools/qs-tester/docsync/tests/test_python_workspaces.py`:

```python
"""invocation/python and pubsub/python are uv workspaces, not two loose projects.

Each holds two apps in subdirectories while `diagrid dev run` runs from the parent
directory, so the virtual environment has to live at the parent. A workspace root
gives both apps one lock and one venv, which is what makes a single
`uv sync --all-packages` able to serve both. See
docs/superpowers/specs/2026-07-31-python-quickstart-uv-workspaces-design.md.
"""

import tomllib

import pytest
import quickstarts as qs

# api -> the app subdirectories that must be declared as workspace members
WORKSPACES = {
    "invocation": ["client", "server"],
    "pubsub": ["publisher", "subscriber"],
}


@pytest.mark.parametrize("api,members", sorted(WORKSPACES.items()))
def test_workspace_root_declares_both_members(api, members):
    root = qs.REPO_ROOT / api / "python" / "pyproject.toml"
    assert root.is_file(), f"{api}/python/pyproject.toml is missing"
    data = tomllib.loads(root.read_text())
    assert data["tool"]["uv"]["workspace"]["members"] == members
    # A [build-system] would make uv try to build the root and members as
    # distributions; they are intentionally non-packaged.
    assert "build-system" not in data


@pytest.mark.parametrize("api,members", sorted(WORKSPACES.items()))
def test_single_lock_lives_at_the_workspace_root(api, members):
    base = qs.REPO_ROOT / api / "python"
    assert (base / "uv.lock").is_file(), f"{api}/python/uv.lock is missing"
    for member in members:
        assert not (base / member / "uv.lock").exists(), (
            f"{api}/python/{member}/uv.lock must be deleted — "
            "the workspace root owns the single lock"
        )
```

- [ ] **Step 3: Create the invocation workspace root**

Create `invocation/python/pyproject.toml`:

```toml
# Workspace root for this quickstart's two apps. It exists so the virtual
# environment lives here, next to invocation-quickstart.yaml, which is the
# directory `diagrid dev run` runs from: `uv run` puts .venv/bin on PATH and the
# bare `uvicorn` command in the dev config resolves from it. Nothing is activated.
#
# ALWAYS sync from here with `uv sync --all-packages`. A sync from inside client/
# or server/ resolves up to this root but installs only that one member, and uv is
# exact by default, so it UNINSTALLS the other app's dependencies. That is what
# broke the client with "ModuleNotFoundError: No module named 'requests'".
[project]
name = "invocation-python"
version = "0.1.0"
requires-python = ">=3.12"

[tool.uv.workspace]
members = ["client", "server"]
```
